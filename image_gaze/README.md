# 手机图像眼动预实验 0.1.1

入口：`image_gaze/pilot.html`。这是独立的校准与验证入口，现有 `food2/revised.html` 和正式食物实验保持原样。

使用 iPhone Safari 打开 HTTPS 网址，默认选轻量图像模型。允许摄像头后先做两轮九点校准，再做一轮九点独立验证。结束时下载完整 JSON，无论通过与否都保留。换模型需要从头重做，不能把同一次验证结果用来调整当前个人模型。

## 0.1.1 运行修复

每帧处理后显式让出浏览器任务队列，避免无效质量或 ROI 分支在 FaceMesh 快速完成时形成连续微任务，阻止准备倒计时和界面刷新。准备阶段增加 3 秒倒计时和采样状态，诊断记录准备心跳及每帧处理阶段。该修复不改变模型、校准采样窗口或验证门槛；不能解除单次同步原生推理自身的阻塞。实际 iPhone 表现仍需新备份确认。

## 实现

- 同一个未镜像摄像头画面先经现有 MediaPipe FaceMesh 定位脸眼 ROI，再裁剪 RGB 脸224×224、双眼112×112，附12维矩形参数。
- 加载固定 GazeFollower 提交的真实 `mobilenet_v4.mnn` 或 `base.mnn`，由单线程 MNN WebAssembly 在 Worker 内推理。右眼按原代码要求翻转一次；图像不保存、不上传。
- 网络冻结，保留全部258维输出。每个校准位置的每轮有效帧形成中位数代表。四个事先固定候选（网络前2维或后256维的岭回归）仅通过校准两轮互相留出选择，之后用全部18个代表拟合个人映射。标准化只使用相应训练折。
- 独立验证只评估，不再训练。屏外预测保留，原始预测直接计算误差；不会为了通过而自动放宽门槛。
- 记录摄像头时间、帧捕获/处理完成、目标显示时间、采样窗口、无效原因、运行版本、模型hash和实际目标坐标。切换页面、视口变化、暂停均终止本轮，重新开始需完整校准。

校准和验证位置根据当前浏览器可用高度避开顶部状态栏与底部按钮，全部坐标仍按完整 CSS 视口归一化；范围不足会停止，不会缩小到局部后宣称全屏通过。

## 验证范围

合成张量检查了两个真实模型的全部258输出，原生MNN与WASM最大差约0.000164（当前三个fixture）。浏览器缩放与OpenCV默认线性缩放有少量舍入差异，也会传到网络输出，故不是作者原程序的逐位或论文准确率复现。输入适配细节见 `PREPROCESSING.md`。

`selftest.html` 使用真实 Worker 和模型检查合成数值，不访问摄像头。可选公开测试肖像仅检查 FaceMesh→ROI→图像模型链路；它没有注视真值。该页面的任何通过或速度数值都不代表手机实验精度。

本版同时改变特征、映射和运行链路，是研究原型比较，不能归因于单一因素。iPhone Safari 的实际运行速度、眼镜/反光影响和独立验证误差，必须由新的手机记录确认。

## 本地运行和源码

在仓库根目录启动静态服务器，例如 `python3 -m http.server 8767 --bind 127.0.0.1`，本机访问 `http://127.0.0.1:8767/image_gaze/pilot.html`。手机远程访问必须使用HTTPS。

页面、采样、个人映射、预处理和 Worker 源码都在本目录。`mnn/` 包含实际模型、WASM和许可证。`runtime-source/` 包含桥接 C++、官方来源下载与编译脚本，以及原生对照结果；重编译方法见该目录README。`release-manifest.json` 固定部署文件hash。

源码测试：在本目录执行 `node --test preprocess.test.cjs image-calibration.test.cjs pilot.test.cjs`。测试fixture均为合成数据，不包含参加者备份。
