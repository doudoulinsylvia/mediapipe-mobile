# 手机眼动实验 v2.3.0

本版在 v2.2.0 的稳定采样、每段中位数拟合和 MediaPipe Face Landmarker 对照入口上，增加两轮校准一致性检查、一次成对补采和卡尔曼滤波诊断对照。本文对应 v2.3.0 本地代码与交付包；**不能凭本说明或链接参数认定已经上线，发布状态须核对线上页面实际版本和部署记录。** 原 `index.html`、旧脚本、图片和历史实验数据未改动。

应用版本为 `2.3.0`，几何、拟合和独立验证核心仍为 `2.2.0`。本次没有接入论文中的专用注视预测神经网络，也没有把面部关键点模型等同于注视估计模型。新增规则与滤波参数属于待预实验检验的工程候选，不保证降低误差。

## 入口与运行

解压完整包，在 `mediapipe-mobile-v2` 目录启动静态服务器：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

电脑访问以下路径；手机必须部署到 HTTPS 后使用 Safari / Chrome，不能使用电脑的 localhost 地址或普通局域网 HTTP。

|---|---|---|
| 原检测器＋改进校准 | `/food2/revised.html?pilot=1&v=2.3.0` | `/food3_formal/revised.html?pilot=1&v=2.3.0` |

`pilot=1` 保留完整两轮校准和九点独立验证，但任务缩短为6张评分、6次选择。新版检测器只允许预实验模式，没有自动退回旧检测器的机制。查询参数中的版本号不证明网站已经更新，需同时核对页面显示的版本。

表中的上下／左右描述图片布局，不表示手机竖屏／横屏。改变屏幕方向或视口后必须重新完整校准。

原检测器入口去掉 `pilot=1` 仍为200张评分、150次选择，保留正式任务流程；v2.3.0 尚无实机精度改善证据，正式采集前需完成手机预实验。

## 改进内容

1. **开始前准备。** 点击“准备好了，开始练习”，注视中央圆点；3秒倒计时后还要获得连续稳定结果，随后自动进入首个校准点。练习数据不参与拟合，首点重新等待和积累稳定窗。准备阶段18秒截止，可下载诊断后重试。
2. **每点稳定后采样。** 两轮九点各保留唯一呈现身份。目标画出后先等待600ms，再等待至少600ms且至少12帧的连续有效特征。达到标准后进度环开始填充，并采集至少1400ms的连续稳定结果。
3. **异常中断并留痕。** 无效结果、过长间断、单帧跳变、特征分散或漂移超限会中断采集段，重新等稳。整个1400ms采集段也必须达标。每点自首次呈现起最多12秒，重试不会延长截止。中止段不会进入拟合，其样本和原因仍保留。
4. **每段中位数拟合。** 每个完成段四维眼部特征分别取中位数。每个训练轮实际有9个代表观测，最终有18个；没有把中位数复制成多条样本。仍按整轮交叉检验选择原有两种固定候选，held-out轮分数以及逐点残差使用原始有效帧。代表特征退化会明确失败，不静默退回其他拟合方式。
5. **拟合后检查两轮一致性。** 对每个位置的两个四维中位数，检查四个特征的跨轮差异及同一最终模型映射出的X/Y差异。任一点不通过时，模型暂不启用，也不会进入独立验证或正式任务。失败面板逐点显示差异。
6. **失败位置成对补采，最多一次。** 可以选择将本次失败位置的两轮都重新采集。旧两次呈现被标记为 `superseded`，仍完整保留；不会从旧、新记录中挑选最接近的两次。补采完成后，使用新的18次活动呈现重新拟合、选择候选并检查全部九个位置。若仍未通过，须保存诊断后重新完整校准。输入或模型完整性错误不允许据此进入局部补采。
7. **原始／EMA／Kalman并行对照。** 在相同已记录尝试上分别保存原始映射、现有指数平滑与新卡尔曼输出，并在验证报告中对照误差、点内波动和有效记录数。只有原始映射决定独立验证是否通过及正式停留时间；滤波结果不替换原始坐标。卡尔曼只读取已观测的坐标、时间戳和有效性，不读取目标坐标，不用预测补齐无效帧。
8. **新版检测器对照。** 固定 `@mediapipe/tasks-vision@0.10.32` 与 `face_landmarker/float16/1`，本地资源、GPU、VIDEO、单脸；启用眼部表情系数与面部变换矩阵。它们仍只保存在诊断中，未改变质量判定或作为映射输入，以便比较检测器变化。
9. **保持独立验证。** 原九个验证位置、600ms等待、1400ms采集、质量与恢复期规则、误差门槛不变。验证不使用校准稳定性筛选，不参与中位数拟合、补采位置选择或模型选择，原始坐标保持未裁剪。X/Y平均误差、P95、覆盖率和逐点结果均须检查。
10. **离开页面立即暂停。** preparation/calibration/validation等活动阶段发生pagehide即中止，随后visibilitychange的事件顺序不会留下活动计时器。补采阶段也遵循同样的暂停与截止规则。

## 稳定规则的含义

默认工程候选：每个眼部特征以眼角宽度归一化，P90−P10≤0.06，前后半时间窗的中位数差≤0.025，连续帧变化≤0.08；相邻有效帧间隔≤150ms。600ms窗口保留边界锚帧，以适应33/34ms等不规则帧间隔。整个采集段完成于第一次满足1400ms完整窗口的真实回调。

这些数值描述输入特征稳定性，**不是屏幕定位误差或注视正确性的标准**。连续稳定地看错位置仍可能通过采样规则，因此独立验证不可省略。中位数不能修复整段错误或稳定偏差；升级检测器也不保证更准确。

## 跨轮一致性与滤波的含义

一致性模块固定检查两轮、九个唯一位置、18个唯一呈现，每次呈现至少12条有效且 `fitEligible=true` 的四维原始特征。先逐维取中位数，再进行以下检查：

- 特征差异：每一维的两轮中位数绝对差，除以全部18个代表值在该维的最大值减最小值，须不超过 `0.25`。检查全部四维，避免模型压缩或双眼平均抵消原始差异。跨度不大于 `1e-8` 时明确失败，不进行除零或静默通过。
- 映射差异：同一最终模型预测两轮代表值，X差异须不超过屏宽的 `0.15`，Y差异须不超过屏高的 `0.15`。不裁剪越界预测。数值比较使用固定 `1e-12` 浮点容差。
- 完整性：缺点、重复呈现、非法轮次、非有限值或无效拟合会阻止通过。该检查只使用校准数据；通过仍不意味着已知目标的定位误差合格。

卡尔曼使用X/Y两条恒速状态与实际观测时间间隔；固定参数为 `measurementStd=0.04`、`accelerationStd=1.5`、`initialVelocityStd=0.5`、`maxGapMs=150`。现有EMA时间常数仍为65ms。无效帧清空卡尔曼状态，长间隔或非递增时间戳重新初始化；不生成缺失帧的外推有效记录。状态方差是滤波器假设下的内部量，不能当作测量准确率或实证置信区间。滤波可能减少波动，也可能带来延迟；稳定偏差仍需校准和独立验证发现。

## 数据与复现

继续使用schemaVersion=2，需结合 `appVersion=2.3.0`、`coreVersion=2.2.0` 与 `calibrationProtocol=consistent_two_round_median_v3` 识别新协议。完整备份包含：

- 所有相机结果，包括练习、等待、无效、恢复、过期阶段与中断采集。
- 每点 `attempts`：所有等待结束后的尝试；`fitEligible=true` 表示该次呈现最终完成的稳定采集段。v2.3.0有补采时，还必须同时限定到 `activePresentationIds` 中的活动呈现，才能复现当前拟合；不能混入等待样本或已经被替代的旧呈现。
- `activePresentationIds`：当前九点各两次的18个活动呈现身份。`targets` 保留原始与补采呈现，长度可能超过18；旧记录的 `superseded` / `supersededBy` 保留替代关系。开始补采时活动计划即更新；补采中止后可能不完整，不得作为成功校准重新分析。
- `repairCycles`：补采位置、原／新呈现身份、开始与结束时间、完成或中止原因。每个完整校准区块最多一次成对补采。
- `consistency` / `consistencyHistory`：最新一致性结果，以及补采前后已完成检查各自的活动呈现、拟合结果、固定设置、逐点原始特征差和映射差。重新完整校准产生新校准区块，不覆盖之前区块。
- `samplingWindows`：每次采集开始、结束、状态、原因、sampleIds、全段稳定性；暂停中止的目标也保存状态。
- `samplingSummary`：采集时长、当前拟合纳入数/总尝试数、全部已完成稳定段帧数、活动呈现数、中断重采次数。比较版本时同时报告等待、补采和失败情况，不能只比较成功段。
- 模型 `aggregation=presentation_median`、每折代表观测、原始帧数、候选分数、完整系数、逐点和跨轮诊断。
- 每行 `tracking_engine` / `tracking_diagnostics`：新版检测器的原始表情系数和面部矩阵；后者不是眼球方向、屏幕落点或经过标定的测距结果。
- `preparation_stability` / `calibration_stability` / `calibration_window_id`；会话记录引擎、固定版本、资源地址、配置、实际视频分辨率和视口历史。
- gaze表的 `gaze_x/y_raw`、`gaze_x/y_smooth`、`gaze_x/y_kalman`，以及 `kalman_timestamp/reset/reason/variance_x/variance_y`、`roi_kalman`。校准区块没有已启用模型时，这些坐标不作为有效眼动位置。
- 验证区块的 `filterComparison` 同时保存原始、EMA和Kalman结果及参数；`evaluation` 仍只保存原始映射的通过判定。会话 `filterUse` 声明滤波仅用于诊断。

新增眼部和矩阵诊断会增加JSON体积。图像只在设备本地处理，不保存照片/视频，不自动上传；刷新或关闭会丢失未下载数据。优先下载完整JSON备份。

## 验证与限制

```sh
node --test tests/*.test.cjs
python3 scripts/build-v2-bundle.py --out /path/to/output
```

本次集成172项自动化检查通过，覆盖原流程、稳定窗、跨轮差异、映射压缩、完整性错误、一次成对补采、历史保留、准备超时、页面隐藏、验证隔离、Tasks入口、滤波复位和取消/迟到回调。测试使用合成输入检查程序，不代表设备眼动精度。

已有v2.2.0真实iPhone备份包含legacy和Tasks两种检测器的完整校准与独立验证。用新一致性模块只读回放时，2026-09-12 Tasks的旧独立验证通过3/9个点、新一致性检查拦截8/9个校准位置；2026-09-11 legacy的旧独立验证通过6/9个点、新一致性检查拦截9/9个校准位置。两种已保存候选模型均能生成18个有限代表预测。回放未调整参数、修改原数据、重拟合模型或使用验证帧进行校准。

**这是回顾诊断，不能模拟补采或证明精度改善。** 校准位置c1–c9与独立验证位置v1–v9不同，两类通过数量不能互相替代。新门槛可能明显增加补采时间、疲劳和失败比例，应在新手机预实验中同时报告这些代价、跨轮重复性和独立验证误差。此阶段没有v2.3.0真实iPhone的精度、耗时或内存改善结论。历史诊断文件不纳入网站运行包或自动上传。

此前本地桌面浏览器用Google官方静态人像实际加载GPU Tasks模型成功，输出478关键点、52系数和16个矩阵元素；这仅说明该环境的资源与模型接口可运行，不能替代手机全流程测试。

包内 `shared/tasks-vision/0.10.32/manifest.json` 保存下载来源、npm原始SHA-512与各资源SHA-256。下载时验证了npm包完整性；采集时不会对全部文件重新计算哈希。旧FaceMesh资源仍在原路径。

完整包包含模型、400张图片、新增模块及测试；覆盖包包含新版文件和Tasks资源，需要仓库已有旧FaceMesh资源与图片。`release-manifest.json` 记录完整包各文件SHA-256，`shared/vendor-manifest.json` 记录旧FaceMesh资源SHA-256及本次应用版本。覆盖已有版本前请备份代码。生成的新增文件补丁仅用于原始基准提交51868f7；已经安装v2.1.0及以后版本的仓库不能直接套用新增文件补丁。
